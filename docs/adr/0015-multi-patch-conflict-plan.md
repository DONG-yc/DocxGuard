# ADR 0015：来源绑定的多补丁计划与冲突检测

## 状态

已接受（Day 15，计划层）

## 决策

DocxGuard 为多个文本替换请求引入 `BoundMultiPatchPlan`，使用 `docxguard.multi-bound-plan.v1` 协议。计划保存请求数组、每个操作的完整段落前置条件、目标 Part 和来源 DOCX SHA-256。计划加载时从来源重新规划，再与序列化 JSON 做确定性比较；它不是数字签名或用户批准凭据。

一个批次最多 64 个请求。只要任意请求没有唯一支持的匹配，或同一段落的两个半开区间 `[start, end)` 相交，整个计划就拒绝，不发布部分计划。通过计划的操作按段落和起始偏移倒序排列，使未来的执行器在同一段落中从后往前修改时不会改变前面操作的偏移。

## 取舍

Day 15 将计划协议和冲突检测作为独立里程碑交付。Day 16 扩展现有执行、校验和报告链路，在同一个原始快照上计算每个受影响 Run 的最终文本，再一次性复检和发布。

## 拒绝码

`MPLAN_001` 为空批次，`MPLAN_002` 为数量或序列化上限，`MPLAN_003` 为来源检查失败，`MPLAN_004` 为目标重叠，`MPLAN_005` 为来源哈希不匹配，`MPLAN_006`/`MPLAN_007` 为协议或 JSON 无效。
